# AI 交互开发记录

本项目使用 **Claude Code** (Anthropic Claude) 协作开发。本文档记录了开发过程中的关键 AI 交互，展示如何利用 AI 辅助构建一个完整的 Web 应用。

## 项目背景

为了给准备 KET 考试的大孩子提高背单词效率，结合 AI 技术设计了这个英语听写练习应用。

## 开发时间线

### 第一阶段：项目初始化 (2026-08-22)

**Prompt**: 开发一个web程序，帮助学生练习英语生词，默写功能...

**AI 输出**:
- 项目结构设计
- 数据库 schema
- Flask 路由规划
- 前端页面原型

**人工决策**:
- 选择 Flask + SQLite 技术栈
- 采用原生 HTML/CSS/JS 前端

### 第二阶段：核心功能开发

**Prompt**: 听写默写页面，单词要有中文含义...

**AI 输出**:
- 填空线索生成算法
- 错误频率追踪逻辑
- 学习提示生成（LLM）

**人工决策**:
- 首尾字母提示 → 60% 随机字母提示
- 添加音标显示
- 添加例句展示

### 第三阶段：LLM 集成

**Prompt**: 提取单词失败: Error code: 401...

**AI 调试过程**:
1. 测试不同认证方式
2. 发现 `auth_token` 与 `api_key` 互斥问题
3. 修复 SDK 兼容性问题
4. 添加 prompt 日志记录

**经验总结**:
- AI 能快速定位认证问题
- 需要提供完整的错误信息

### 第四阶段：短文功能

**Prompt**: 增加一个短文页面，对词库的词进行研究...

**AI 输出**:
- 短文生成 prompt 设计
- 中英对照展示
- 高频错误词汇优先融入

**人工决策**:
- 篇幅控制在 300-400 词
- 高频错误词汇占比 30%
- 添加诊断模式验证 prompt

### 第五步：部署与优化

**Prompt**: 部署到 Render.com 出现错误...

**AI 调试过程**:
1. `gunicorn: command not found` → 添加 requirements.txt
2. `ModuleNotFoundError: requests` → 添加依赖
3. `FileNotFoundError: instance/app.log` → 自动创建目录
4. `'typing.Union' object has no attribute` → 修复认证方式

## AI 协作最佳实践

### 1. 提供清晰的上下文
```
✅ 好的 prompt:
   "听写页面，单词要有中文含义，或者英文的翻译"

❌ 差的 prompt:
   "改一下页面"
```

### 2. 提供完整的错误信息
```
✅ "部署出现错误: gunicorn: command not found"
❌ "部署失败了"
```

### 3. 分步骤迭代
```
✅ 每次只改一个功能
❌ 一次性提很多需求
```

### 4. 人工决策与 AI 建议结合
```
✅ AI 提供方案，人工决定是否采纳
❌ 完全依赖 AI 决策
```
